## 2. 项目背景与技术目标

### 2.1 一句话定位
一个温和的个人记录与轻社交平台，用 AI 辅助记录生活、规划理想、与朋友真心交流。

### 2.2 MVP 范围（本次开发的边界）
| 模块 | 必须做 | 明确不做（延后） |
|---|---|---|
| 记录卡 | 创建/编辑/删除、心情、AI 扩写、AI 风格推荐、图片上传（1-3 张）、时间线列表 | 留言、指定送达、匿名 |
| 理想卡 | 创建理想、AI 拆解任务、每日打卡、打卡日历、可见性设置 | — |
| 时间胶囊 | 写信给未来自己、设定开启日期、到期提醒 | 种子信箱（给陌生人） |
| 用户系统 | 注册/登录、个人主页、基础设置 | 关注/粉丝、私信 |

### 2.3 技术目标
1. **2 周内可交付上线**（单人开发，前后端分离两个项目）
2. **单人可维护**：技术栈主流、资料丰富、结构清晰
3. **成本最低**：MVP 不引入 Redis/消息队列/微服务；AI 用 DeepSeek 低价模型
4. **可平滑扩展**：数据模型与接口设计预留二期（社区、复盘、天气图）扩展点
5. **调性一致**：淡蓝、漫画风、简约、去量化、温暖反馈（贯穿 UI 与 AI Prompt 设计）

## 3. 技术选型（最终方案）

> 说明：需求文档原建议后端为 Node.js/FastAPI，经人工确认，**改为前后端分离 + Java Spring Boot**。

### 3.1 总体架构决策
**前后端分离**：前端 Next.js（React）独立项目，后端 Spring Boot 独立项目，通过 REST/JSON 通信。

**为何不选「Next.js 全栈一体化」**：后端已确认为 Java Spring（用户技术栈偏好），故采用前后端分离。

**为何不选「单体」**：前后端分离架构清晰，前端可独立部署 CDN，后端独立扩容，且后续小程序可直接复用后端 API。

### 3.2 分项选型表

| 层级 | 备选方案 | **选定方案** | 选择理由 |
|---|---|---|---|
| 前端框架 | Nuxt.js / Vite SPA | **Next.js 16 (App Router) + React 19 + TypeScript** | 生态最成熟；SSR/SEO 好；后续小程序可用 Taro(React) 复用组件 |
| 后端框架 | Node/FastAPI | **Spring Boot 3.5 + JDK 21 + Maven** | 用户技术栈；生态完善；安全/事务/定时任务开箱即用 |
| 持久层 | JPA / 原生 MyBatis | **MyBatis-Plus 3.5** | 单表 CRUD 零 SQL、复杂查询可手写 SQL，国内事实标准 |
| 数据库 | PostgreSQL / SQLite | **MySQL 9.5** | Java 生态最主流，MyBatis-Plus/云厂商生态完善 |
| 缓存 | Redis | **MVP 暂不引入** | <50 用户，MySQL 足够；AI 次数/验证码用表计数，二期再上 Redis |
| 认证 | NextAuth / 自建 | **Spring Security 6 + JWT** | 后端统一鉴权，前后端分离标准方案 |
| AI 大模型 | 通义千问 / GPT | **DeepSeek API（deepseek-chat）** | 低价、国内直连、中文效果好 |
| AI 框架 | 原生 HTTP / OpenAI SDK | **Spring AI 1.1.x（原生 DeepSeek 启动器）** | 统一 ChatClient/流式/结构化输出，换模型只改配置 |
| 文件存储 | OSS / R2 | **开发期本地磁盘，生产预留阿里云 OSS** | 部署未定，OSS 待上线时定 |
| API 文档 | — | **Knife4j（Swagger 增强）** | 国内 Java 常用，接口自测方便 |
| 前端状态 | Redux / Context | **TanStack Query 5（服务端）+ Zustand 5（本地）** | 服务端状态缓存/重试自动化，本地状态轻量 |
| UI 方案 | 自绘 / 组件库 | **Tailwind CSS 4 + shadcn/ui 定制淡蓝漫画主题** | 快速定制漫画风，可完全掌控视觉 |

### 3.3 MVP 明确「不引入」清单（及理由）

| 项 | 理由 | 二期触发条件 |
|---|---|---|
| Redis | 用户量小，缓存收益低，运维成本高 | 用户 > 500 或接口出现性能瓶颈 |
| 消息队列（MQ） | 无异步重活（除定时任务外） | 引入社区/推送等大批量异步 |
| 微服务/注册中心 | 单人项目，单体足够 | 团队协作或多业务线 |
| Elasticsearch | 无全文检索需求 | 讨论社区上线 |
| 对象存储 OSS | 部署未定，本地磁盘可跑通 | 上线部署时启用 |

### 4.3 后端架构

**分层结构**（Controller → Service → Mapper）：

```
backend/
└── src/main/java/com/cloudrecord/
    ├── CloudRecordApplication.java
    ├── common/          # Result<T>、错误码、全局异常、业务异常
    ├── config/          # Security、MyBatis-Plus、CORS、定时任务、Knife4j
    ├── security/        # JWT 工具、登录拦截器、用户上下文
    ├── controller/      # Auth/User/Record/Ideal/Capsule/Ai/File
    ├── service/         # 业务接口 + impl
    ├── mapper/          # MyBatis-Plus Mapper 接口
    ├── entity/          # 数据库实体
    ├── dto/             # 请求体对象
    └── vo/              # 响应视图对象
```

**关键公共组件**：
- **统一响应体 `Result<T>`**：`{ code, message, data }`，`code=0` 成功，非 0 失败
- **全局异常处理器**：`@RestControllerAdvice` 统一捕获业务异常/参数校验异常/未知异常
- **登录拦截器**：解析 `Authorization: Bearer <JWT>`，注入当前用户到上下文；白名单放行登录/注册/验证码
- **CORS 配置**：允许前端开发端口跨域
- **AI 统一封装**：`AiService` 注入 Spring AI `ChatClient`，统一限流、计次、降级、协议规范化（详见第 7 章）

### 4.4 前后端交互约定

| 约定 | 说明 |
|---|---|
| 协议 | REST + JSON（AI 场景用 SSE） |
| 鉴权 | `Authorization: Bearer <access_token>`；过期用 refresh_token 换取新 token |
| 统一响应 | `{ code, message, data }`，`code=0` 成功 |
| 错误码 | 见第 12 章，前端按 code 展示提示 |
| 分页 | `page`(1 起) + `size`，返回 `{ list, total, page, size }` |
| 流式 | AI 扩写/拆解走 SSE（`text/event-stream`），前端逐字渲染 |
| 时区 | 统一 UTC 存储，前端转本地时区展示 |

## 6. 核心模块详细设计

### 6.1 用户模块

**功能点**：注册（邮箱验证码）、登录、JWT 刷新、个人主页、基础设置。

**数据流（注册）**：
```
填写邮箱/昵称/密码 → 点击"获取验证码" → 后端发验证码（存 email_code，10 分钟有效）
→ 提交注册 → 校验验证码 → BCrypt 加密密码 → 写 user → 返回 JWT
```

**数据流（登录）**：邮箱+密码 → 校验 → 签发 access_token（2h）+ refresh_token（14d）→ 前端存 refresh_token，access_token 过期自动刷新。

**关键边界与异常**：
- 验证码错误/过期 → 明确提示，支持重发（60s 频控）
- 邮箱已注册 → 提示"该邮箱已注册，可直接登录"
- 未登录访问受保护接口 → 返回 401，前端跳登录

### 6.2 记录卡模块

**功能点**：CRUD、心情设置、AI 扩写/润色、AI 风格推荐、图片上传（1-3 张）、时间线列表。

**数据流（创建卡片）**：
```
输入正文 → 选择心情 →（可选）点"AI 扩写"生成建议 → 采纳/丢弃
→（可选）点"AI 风格推荐"选择风格 → 上传图片（1-3 张）
→ 提交 → 写 record_card + card_image → 返回卡片
```

**AI 扩写交互**：用户点"AI 扩写"→ 后端调 DeepSeek（SSE 流式）→ 前端实时渲染建议文本 → 用户点"采纳"覆盖正文 / "丢弃"保留原文（不落库中间态，采纳才覆盖 `content`）。

**图片上传**：前端校验（类型 jpg/png/webp、单张 ≤ 5MB、最多 3 张）→ 后端存本地磁盘（生产 OSS）→ 返回 url → 关联 card_image。

**边界与异常**：
- 空内容不可提交（前后端双重校验）
- AI 失败降级：提示"AI 暂时不可用"，保留用户已输入原文，不阻塞保存
- 图片超限：前端即时提示，后端二次校验

### 6.3 理想卡模块

**功能点**：创建理想、AI 拆解每日任务、每日打卡、打卡日历、可见性设置。

**数据流**：
```
创建理想（标题/描述/可见性）→ 点"AI 规划" → 调 DeepSeek 拆解为任务列表
→ 写 ideal + ideal_task → 用户每日点"今日打卡" → 写 check_in → 日历展示
```

**打卡规则**：每理想每天最多一次打卡；当天未打卡可补打（当天内）；日历按 `check_in.check_date` 聚合展示当月打卡分布。

**可见性**：`PRIVATE` 仅自己可见；`PUBLIC` 可在个人主页对外展示（MVP 无社交，但为二期预留字段）。

**边界与异常**：
- AI 拆解失败 → 允许手动添加任务，理想可正常创建
- 重复打卡 → 幂等处理（同一天重复点击只更新状态，不新增记录）

### 6.4 时间胶囊模块

**功能点**：写信给未来自己、设定开启日期、到期提醒。

**数据流**：
```
写信（标题/内容/开启日期）→ 开启日期必须 ≥ 明天 → 写 time_capsule
→ 后端每日定时任务扫描 open_date <= today 且 remind_sent=0 → 发提醒（站内+邮件）
→ 到期后用户进入详情可见内容，标记 is_opened=1
```

**提醒机制**：Spring `@Scheduled` 每日扫描一次；「站内提醒」落个人主页提示，「邮件提醒」复用邮箱（需配置 SMTP，MVP 可先仅站内）。

**边界与异常**：未到开启日期的胶囊内容不可见（后端强制校验 `open_date`）。

## 7. AI 能力设计（核心差异化）

### 7.1 DeepSeek 接入

| 项 | 值 |
|---|---|
| 接口协议 | OpenAI 兼容（`https://api.deepseek.com/v1/chat/completions`） |
| 模型 | `deepseek-chat`（DeepSeek-V3 系列） |
| 认证 | `Authorization: Bearer <DEEPSEEK_API_KEY>`（仅存后端环境变量） |
| 建议参数 | 扩写 `temperature=0.7`、`max_tokens=1024`、`stream=true`；风格/拆解 `temperature=0.2`、`max_tokens=512` |
| SDK | Spring AI 1.1.x（`spring-ai-starter-model-deepseek` 原生接入 DeepSeek，注入 `ChatClient`） |

**调用统一封装**：后端 `AiService` 注入 Spring AI `ChatClient`，提供 `chatStream(prompt)`（返回 `Flux<String>`）与 `chatJson(prompt, type)`（结构化输出）两个方法，四类场景复用，便于统一限流、日志、降级。

### 7.2 四类 AI 场景与 Prompt 设计

> 系统人设（所有场景共用的 System Prompt）：
> 「你是『云记录』的温柔 AI 助手。语气温和、真诚、不浮夸、不评判，帮助用户记录生活和规划理想。回答用简体中文，口语自然，像朋友一样。」

#### 场景一：AI 扩写/润色（EXPAND）
**输入**：`{ 心情, 原始文本 }`
**Prompt 模板**：
```
用户写了一段生活记录，心情是「{mood}」。
请在保留原意和语气的基础上，把这段话扩写/润色得更生动自然，
适当补充细节和感受，但不要编造事实，长度控制在原文的 1.5~2 倍。
直接输出润色后的文本，不要任何解释。

原文：
{content}
```

#### 场景二：AI 风格推荐（STYLE）
**输入**：`{ 心情, 文本摘要 }`
**Prompt 模板**：
```
根据用户的心情「{mood}」和记录内容，从以下风格中推荐最合适的一个卡片风格，
并给出 5~15 字的推荐理由。
风格列表：warm-sunny(暖阳橙)、quiet-blue(静谧蓝)、mint-fresh(薄荷绿)、
sakura-pink(樱花粉)、night-purple(夜空紫)、paper-white(素白)。

严格按 JSON 输出：{"style_key":"...","reason":"..."}，不要输出其他内容。

记录内容：{content}
```
> 后端解析 JSON，若解析失败则回退默认风格，不阻塞流程。

#### 场景三：理想拆解（IDEAL_SPLIT）
**输入**：`{ 理想标题, 理想描述 }`
**Prompt 模板**：
```
用户的理想是「{title}」，描述：{description}。
请把这个理想拆解成 5~8 个可执行的小步骤/每日任务，
每个任务具体、可衡量、适合每天完成。
严格按 JSON 数组输出：[{"content":"任务内容"}, ...]，不要输出其他内容。
```

#### 场景四：任务拆解（可并入场景三，亦可独立）
当用户对单个任务说"今天怎么开始"，复用场景三思路输出 2~3 个今日小动作。

> 结构化输出：风格/拆解场景用 Spring AI 的 `BeanOutputConverter` 注入目标 schema、解析为 DTO；DeepSeek 的 function calling 不稳定，故不用 tool calling，统一走「提示词要求输出 JSON + 后端容错解析」。

### 7.3 流式输出（SSE）
- 仅「AI 扩写」走 SSE（`text/event-stream`）；风格推荐/理想拆解走非流式 JSON，一次性返回，前端 loading 态
- 后端用 Spring AI `chatClient.prompt().stream().content()` 得到 `Flux<String>`，逐 token 桥接到 `SseEmitter`，规范化为自有协议：`{"type":"delta","content":"..."}` / `{"type":"done"}` / `{"type":"error","message":"..."}`
- 前端用 `@microsoft/fetch-event-source`（支持 POST + 断线重连）逐字渲染，避免长时间等待
- 失败降级：SSE 中断时，前端保留已生成内容，提示"生成中断，可重试"

### 7.4 成本控制与安全
1. **每日免费次数**：默认每用户每场景 20 次/天（MVP 可调），超限提示"今日 AI 次数已用完，明天再来～"
2. **单次 token 上限**：`max_tokens` 设上限，防止超长输出
3. **结果缓存**：MVP 暂不引入（用户量小，靠每日次数 + token 上限控成本），二期再按 `(scene, 用户输入hash)` 命中缓存
4. **API Key 安全**：仅存后端环境变量，前端永不接触；后端代理转发
5. **失败降级**：AI 不可用/超时，功能降级为"手动模式"（保留原文、手动选风格、手动加任务），**不阻塞核心功能**

## 9. 开发流程与思路（2 周排期细化）

### 9.1 开发顺序原则
1. **先数据库后接口**：先定表结构与建表 SQL，再写接口，避免返工
2. **先后端后前端**：后端接口先行，前端用 Knife4j 自测联调
3. **先骨架后功能**：第一天搭好前后端骨架 + 登录打通，再逐个模块填充
4. **AI 后置**：AI 依赖接口，在记录卡/理想卡基础功能跑通后再接入
5. **每天可运行**：每天结束时保证项目能启动、无阻塞性 bug

## 12. 安全与性能

| 项 | 措施 |
|---|---|
| 密码安全 | BCrypt 加密存储，永不明文 |
| JWT | access_token 2h + refresh_token 14d；刷新后旧 token 失效 |
| SQL 注入 | MyBatis-Plus 参数化查询，禁止字符串拼接 SQL |
| XSS | 前端富文本/正文渲染转义；后端校验输入长度 |
| 图片安全 | 校验类型/大小/文件名，存储路径随机化 |
| AI 限流 | 每用户每日次数限制 + 单次 token 上限 + 接口级防刷 |
| 越权防护 | 所有资源按 `user_id` 归属校验（查/改/删他人数据返回 404/403） |
| 冷启动兜底 | 首页/列表空状态配温暖引导文案，不显示"暂无内容" |
| 性能 | MVP 无高并发，重点保证单查询走索引（user_id、联合唯一键） |

**统一错误码约定**：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录/token 失效 |
| 403 | 无权限（越权访问） |
| 404 | 资源不存在 |
| 429 | AI 次数超限/验证码频控 |
| 500 | 服务端异常 |
