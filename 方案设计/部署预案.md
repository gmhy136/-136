# 《云记录》部署预案

> 版本：v1.0　|　日期：2026-10-14　|　状态：预案（本阶段**不实际落地** Docker 文件，仅交付方案，本地已跑通）
> 承接：[MVP 开发方案](MVP开发方案.md) §6.2「P7 收尾 · 部署预案」

---

## 1. 目标与定位

本地开发已完成闭环：MySQL → Spring Boot（8080）→ Next.js（3000）。本预案给出**可复现的单机部署方案**，供 D14 或后续上线时落地。原则：

- **单机优先**：一台服务器即可跑通，不引入 K8s 等编排。
- **配置外置**：数据库口令 / JWT 密钥 / DeepSeek Key 全部走环境变量，镜像内不含明文。
- **静态 + 反代**：前端产物由 Nginx 托管，`/api`、`/uploads` 反代到后端。

---

## 2. 部署拓扑

```
浏览器
   │  https://cloud.me
   ▼
 Nginx (80/443)
   ├─ /            → 前端静态文件（next build 产物）
   ├─ /api/*       → 反向代理 → backend:8080
   └─ /uploads/*   → 后端 uploads 目录（静态或再反代）
        │
        ▼
 Spring Boot (backend:8080)
   ├─ 定时任务 CapsuleRemindJob（单实例）
   └─ MySQL 9.5 (mysql:3306)
        uploads/ （挂载卷持久化）
```

## 3. Docker 化草案

### 3.1 backend/Dockerfile（草案）

```dockerfile
# ---- 构建 ----
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn -q dependency:go-offline
COPY src ./src
RUN mvn -q package -DskipTests

# ---- 运行 ----
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
VOLUME /app/uploads
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 3.2 frontend/Dockerfile（草案）

```dockerfile
# ---- 构建 ----
FROM node:22-alpine AS build
WORKDIR /app
RUN corepack enable
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile
COPY . .
ARG NEXT_PUBLIC_API_BASE=/api/v1
ENV NEXT_PUBLIC_API_BASE=$NEXT_PUBLIC_API_BASE
RUN pnpm build

# ---- 运行：Nginx 托管静态 + 反代 ----
FROM nginx:alpine
COPY --from=build /app/.next/standalone /app
COPY --from=build /app/.next/static /app/.next/static
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

> 说明：`next.config.ts` 需开启 `output: 'standalone'` 才能产出 `.next/standalone`；本阶段未改动该配置，落地时再评估。

### 3.3 docker-compose.yml（草案）

```yaml
services:
  mysql:
    image: mysql:9.5
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: cloudrecord
    volumes:
      - mysql-data:/var/lib/mysql
      - ../backend/src/main/resources/db/schema.sql:/docker-entrypoint-initdb.d/schema.sql:ro
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 5s
      retries: 10

  backend:
    build: ../backend
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/cloudrecord?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
      SPRING_DATASOURCE_USERNAME: root
      SPRING_DATASOURCE_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
      SPRING_AI_DEEPSEEK_API_KEY: ${DEEPSEEK_API_KEY}
      APP_UPLOAD_DIR: /app/uploads
    volumes:
      - uploads-data:/app/uploads
    depends_on:
      mysql:
        condition: service_healthy

  frontend:
    build:
      context: ../frontend
      args:
        NEXT_PUBLIC_API_BASE: /api/v1
    ports:
      - "80:80"
    depends_on:
      - backend

volumes:
  mysql-data:
  uploads-data:
```

### 3.4 nginx.conf（草案）

```nginx
server {
  listen 80;
  root /app;

  location /api/ {
    proxy_pass http://backend:8080/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  location /uploads/ {
    proxy_pass http://backend:8080/uploads/;
  }

  location / {
    try_files $uri $uri.html $uri/ /index.html;
  }
}
```

## 4. 环境变量清单

| 变量 | 用途 | 必填 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 口令 | 是 |
| `JWT_SECRET` | JWT 签名密钥（≥32 字节） | 是 |
| `DEEPSEEK_API_KEY` | DeepSeek Key（不填则 AI 降级） | 否 |
| `SPRING_DATASOURCE_URL/USERNAME/PASSWORD` | 后端连库 | 是 |
| `APP_UPLOAD_DIR` | 上传目录（挂载卷） | 是 |
| `NEXT_PUBLIC_API_BASE` | 前端 API 前缀（构建期注入） | 是 |

> 本地 `.env.local` / `application-dev.yml` 与上述变量一一对应，见 `application-dev.yml.example`。

## 5. 上线前待办 / 风险

1. **定时任务单实例**：`CapsuleRemindJob` 若后端横向扩容会重复提醒，MVP 保持单实例即可；扩缩容需改为分布式锁或独立调度。
2. **上传持久化**：`uploads/` 必须挂载卷，否则容器重建丢失图片。
3. **密钥管理**：生产用密钥管理服务 / CI 注入，不入库、不进镜像。
4. **HTTPS**：Nginx 层加证书（Let's Encrypt）终止 TLS。
5. **CORS**：当前后端 CORS 面向本地开发；经 Nginx 同源反代后应收紧为同源，避免任意跨域。
6. **DeepSeek 依赖**：AI 全部带降级，Key 缺失或超时不影响记录/理想/胶囊核心功能。
7. **数据库迁移**：MVP 用 `schema.sql` 全量建表；后续迭代建议引入 Flyway/Liquibase 做增量迁移。

## 6. 结论

本预案给出「Nginx + Spring Boot + MySQL + 卷持久化」的单机可复现方案与三份 Docker 草案。**当前阶段仅文档交付**；落地时需（1）开启 Next.js `standalone` 输出，（2）核对 Docker 内网地址与 CORS，（3）补齐证书与密钥管理。
