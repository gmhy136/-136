# 《云记录》二期 · 问答游戏 + 好友系统 开发方案

> 版本：v1.0　|　日期：2026-10-14　|　定位：执行视角的开发路线图
> 承接文档：[MVP 开发方案](MVP开发方案.md)、[方案设计文档](../需求文档/方案设计文档.md)
> 本功能从 MVP backlog 提出（MVP 方案 §3 明确「问答游戏」为二期不做项）。沿用 MVP 的技术栈与分层约定，不重复展开。

---

## 1. 定位

本功能**不是**把产品整体转型为社交产品，而是新增一个**独立的社交模块**：好友之间互相出题、答题。现有「记录卡 / 理想 / 胶囊 / 心情 / 主页」等私密自省功能保持不变。

## 2. 已确认决策

| 决策点 | 结论 |
|---|---|
| 好友模型 | 双向确认（申请 → 接受） |
| 添加好友方式 | 邮箱搜索 + 邀请链接（后续再完善） |
| 答题结果 | 答题人可匿名；不做排名（好友间互看不到成绩） |
| UI | 无原型图，按现有纸感浅蓝设计系统定稿 |
| 入口 | 新增一个导航项 |

## 3. 数据模型（新增 7 张表）

> 全部追加到 `backend/src/main/resources/db/schema.sql`，沿用 utf8mb4 / BIGINT 自增 / MyBatis-Plus 自动填充约定。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `friendship` | requester_id, addressee_id, status(PENDING/ACCEPTED/REJECTED) | 双向确认；uk(requester,addressee) 防重复 |
| `friend_invite` | inviter_id, token, expires_at | 邀请链接（7 天有效，可复用） |
| `quiz` | owner_id, title, description, status(DRAFT/PUBLISHED), published_at | 发布即进朋友圈 |
| `quiz_question` | quiz_id, type(CHOICE/JUDGE), content, judge_answer, sort_order | 判断题存 judge_answer(1 对 / 0 错) |
| `quiz_option` | question_id, label, is_correct, sort_order | 选择题选项 |
| `quiz_answer` | quiz_id, user_id, anonymous, score | 一次作答；uk(quiz,user) 限答一次 |
| `quiz_answer_item` | answer_id, question_id, chosen_option_id, chosen_bool, is_correct | 每题作答明细 |

## 4. 接口明细（后端 `/api/v1`）

| 模块 | 方法 + 路径 | 说明 |
|---|---|---|
| 好友 | `GET /friends` | 我的好友列表（已接受） |
| | `GET /friends/requests` | 收到的 + 发出的申请 |
| | `GET /friends/search?email=` | 邮箱搜索用户 |
| | `POST /friends/requests` | 发申请（body `{email}`） |
| | `POST /friends/requests/{id}/accept` / `reject` | 接受 / 拒绝 |
| | `DELETE /friends/{friendId}` | 删除好友 |
| | `POST /friends/invites` | 生成邀请链接 |
| | `POST /friends/invites/{token}` | 点击邀请链接（生成一条「邀请人→我」的申请） |
| 出题 | `POST /quizzes`、`GET /quizzes`、`GET/PUT/DELETE /quizzes/{id}`、`POST /quizzes/{id}/publish` | 题库 CRUD + 发布 |
| 朋友圈 | `GET /feed` | 好友 + 我发布的题 |
| 答题 | `GET /quizzes/{id}/play`、`POST /quizzes/{id}/answers`、`GET /quizzes/{id}/answers`、`GET /quizzes/{id}/my-answer` | 答题页（不含答案）/ 提交 / 出题人看答题情况 / 我的作答 |

## 5. 可见性规则

- **出题人**：看到谁答了 + 各自得分；匿名者显示「匿名好友 · 对 N 题」。
- **答题人**：交卷后立刻看到自己的得分与每题对错。
- **好友之间**：互看不到成绩（无排名）。
- **限答一次**：每张题每人只能提交一次。

## 6. 前端页面（新增）

| 路由 | 说明 |
|---|---|
| `/friends` | 好友列表 + 收到的申请 + 邮箱搜索 / 邀请链接 |
| `/invite/[token]` | 邀请落地页（登录后接受邀请） |
| `/feed` | 朋友圈（好友 + 我的题） |
| `/quiz` | 我的题库 |
| `/quiz/new` | 出题编辑器（选择题 / 判断题） |
| `/quiz/[id]` | 详情（出题人看答题情况 / 答题人看结果） |
| `/quiz/[id]/play` | 答题页 |

新增导航项「朋友」作为入口（具体命名与布局在阶段三按设计系统定稿）。

## 7. 分阶段实施（后端 TDD：先测试后实现）

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| **P1 好友系统** | friendship / friend_invite 表 + FriendService + 单测 + 控制器 | 邮箱申请→接受→好友列表全流程单测通过 |
| **P2 出题+自测** | quiz 三表 + QuizService 判分 + 单测 | 建题（选择/判断）→ 自答 → 判分正确 |
| **P3 朋友圈+答题** | feed + 发布 + 好友答题 + 匿名结果 | 好友可见/可答、匿名隐藏身份 |
| **P4 前端** | 上述页面 + 导航项 + 联调 | 全流程走通 |
| **P5 通知** | 站内红点（好友申请、有人答题） | 红点展示正确（推送后置） |

## 8. 验收标准

- **好友**：邮箱搜索加好友（申请 / 接受 / 拒绝 / 删除）+ 邀请链接落地，全流程走通。
- **问答**：出题（选择题含多选项、判断题）→ 发布朋友圈 → 好友答题 → 出题人看答题情况（含匿名）。

## 9. 风险与裁剪

- **冷启动**：问答依赖好友同时在用，先保证「自己出题自己答」可用，再靠邀请链接拉动。
- **UGC**：发布内容仅好友可见，MVP 不做举报 / 审核；后续需要再补。
- **严格范围**：不做排名、不做私信、不做关注；通知先站内红点，推送后置。
